## Current state: lobby world, no game rules yet
The repo now holds the Break for Cars lobby: the lego island with its plazas, six plots (one built player base), the HUD and effects, on top of the player / physics / sky base. There are no windows, no audio, no networking, no saves and no game rules yet (HUD buttons toast "coming soon"; values are placeholders). The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN; `VITE_SERVER_URL` (dev builds only) points at a local backend. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel). Game slug `break-for-cars` (`GAME_SLUG`, = the hosting id `LEGION_GAME_ID`).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the world (`WATER`, `SPAWN`, `SPAWN_FACING`, `LOBBY`, `BLOCK_THEMES`, `RARITY_COLORS`, `BASE` (incl. `floors`, `stairs`), `GARAGE_SKINS` + `SKINS_PAD` (garage skins: colours, income mult, Index % / price to unlock; `game/baseskins.js` window opened from the "Bases" pad), `FEATURED_BLOCKS`, `CARS`, `HUD_DEMO`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). Every feature but Gems is wired (docs.bloxity.io): `init({ gameSlug })` (environment never guessed from the hostname) + `registerFeature('emotes')` right after, loading steps / `loadingEnd` + `gameplayStart` (`notifyFirstFrame`), auth (user/guest, `getToken` for the server), settings `master_volume`, `music_volume`, `graphics_quality`, `camera_sensitivity`, `show_fps` (main.js applies them; the game has NO settings/pause menu of its own), avatar + proportion events, player events (`respawn_request`, `play_emote`, `pointer_lock_changed`), chat (`onChat`: bubbles over heads, `bubble.js`), ads (`onAdBreak` pauses + mutes the game; `declareScreens(AD_SCREENS)` + `showScreen('panel' | 'gameplay')` from main.js; rewarded ads for the Spin Wheel's "Watch Ad", server-verified), leaderboards (`define(LEADERBOARDS)` on boot = trophy button; the server reports scores; `topScores` fills the north plaza boards), friend-join toasts (`playerJoined` / `playerInRoom`), matchmaker (`resolveServerEndpoint`, `locateRoom`, `updateRoom`), Escape -> `showMenu(true)`, reserved areas. No death screen: the player cannot die (a fall just respawns). See `BLOXITY_CODE_METADATA.md`.
- Multiplayer (rooms of six, `NET` in config): `net.js` joins `world` through the matchmaker (or `?roomId=`), relays pose / hands (`game.loadout()`) / swings / emotes / Bloxity look / the garage (`game.baseSnapshot()`) / scores, and exposes the roster. Six garages stand on the island (`lobby.bases`, one per `LOBBY.plots`, static meshes baked per garage); the server assigns one per player (`plot`) and main.js `followPlot` moves the game there (`game.moveTo(base)`: views reparented, conveyor / unlocks / lights / event roller carried over; offline it stays on `LOBBY.homePlot`). `remotePlayers.js` draws the others (Bloxity rig, name tag, pickaxe in hand or on the back, swing, carried block / held car, emotes, chat bubbles); `remoteBases.js` draws their garages read-only (bay blocks + health, cars + labels, bought bays, floors + garage skin (`fl` / `sk` in the snapshot), conveyor skin + luck, billboard name + income) and the free ones; `remoteBases.forget(i)` redraws a garage the local game just left (moveTo clears it).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, lobby (`buildLobby`), player body -> avatar (async, swaps in when ready) -> game -> net -> loop (physics, interpolate player, avatar animator, garage assignment + remote bases / players, camera, sea ripples, lighting, bloom render). An ad break skips the simulation (draws only). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z), `setView(yaw, pitch, distance)` (camera orbit), `lobby`, `lighting`. Dev server: the `break-for-cars` entry in the parent folder's `.claude/launch.json` (port 5231, dev mode).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Sea + clouds**: `world.js` `createWorld(scene)` (`.update(dt, elapsed)` scrolls the ripples, `.setSeaColor`).
- **Lobby** (`lobby/`, layout + colours in `LOBBY` / `BASE` / `BLOCK_THEMES` / `CARS` in config): a lego island. `lego.js` `studify`/`brick` draw studs in the fragment shader from WORLD position on every upward face (same stud size on any box). `ground.js` grass slab, two-lane road with lane chevrons and curbs, a plaza at each end, six grass plots in a brown border, each with a garage. `nature.js` lego trees/pines/bushes/rocks, seeded and baked. `leaderboards.js` north plaza (Cash / PlayTime / Total Income; placeholder rows until Bloxity's boards answer, `lobby.boards[].setEntries`). `southplaza.js` stalls (Pickaxes Shop, Sell) with shopkeepers and ground rings, "Next Event" countdown board, Fuse Machine, Spin Wheel (spins when you step in its ring); `zones` = the rings. `base.js` one garage per plot (`buildBase`, static meshes baked per material; `setOwner` / `setIncome` billboard, `setLit` interior lights only on the local player's, `lockBay` / `unlockBay`, `setFloors(n)` extra storeys from `BASE.floors` (10 bays each, bay `level`; a lego stair with a hidden ramp collider climbs each along the open front, alternating sides; floors not bought are hidden with colliders off; roof + billboard ride on top; `floorPlates` = where the next floor is bought), `setSkin(id)` recolours the garage's own materials from `GARAGE_SKINS`): glass showroom garage (truss mullions, parking bays + green collect pads, owner billboard), apron, block conveyor with tunnel boxes and weighted rarity blocks (labels, sparkles, Secret blocks call `onAnnounce`), two limited cars. `cars.js` procedural cars: lofted body + cabin surfaces per style (`STYLES`: top profile, plan roundness, fenders cut by real wheel arches), details (glass, lights, vents, intakes, panel gaps, neon) laid on the surfaces as patches, lathed wheels; merged to one geometry per material role and cached per style (~14 draw calls, ~23k tris a car). `fx.js` GPU sparkle fields (`fxView`/`fxBoost` set by main.js) + a burst pool. `playerfx.js` hammer + swirl on the player. `paint.js` canvas painters. `index.js` `buildLobby` assembles it all and reports ring zones.
- **HUD** (`hud/`): `hud.js` + `hud.css` (To Shop / To Plot / spin wheel, left tiles, offers, money, hotbar with keys 1-7, toast, announcement banner; values from `HUD_DEMO` until the economy exists). One scale unit `--s`; short-screen and portrait-touch media rules keep it clear of the touch controls; the top row and left column dodge `bloxity.onReservedAreas` (and the top row also the touch layer's corner buttons). Phone portrait: To Shop / To Plot stack in a column right of Bloxity's chat with the spin wheel under it, Index / FREE! / Auto Swing one row under the chat. Phone landscape + touch: spin / calendar / settings and Index / FREE! / Auto Swing form a two-row block on the right between the corner buttons and the thumb cluster, money sits under the chat, so the joystick and thumb corners stay empty. `thumbnails.js` renders HUD icons from the 3D models once.
- **Sound effects** (`game/audio.js`, all procedural Web Audio): natural voices only (mallet / knock / coin / brown-noise thud / air whoosh, soft low-pass + small room reverb, no square or saw waves), slight random pitch per call. One delegated listener gives every clickable element (button, `.touch-btn`, anything `cursor: pointer`; not `data-sfx="off"`) a hover tick (mouse only) and a press "thock", so new windows need no wiring; windows call `blip()` on open and `close()` on close. `game/movesfx.js` (called from the main loop) plays footsteps on the animator's stride cadence (grass vs hard lego by feet height), jump, landing (scaled by fall speed) and respawn from `player.jumps` / `player.respawns`.
- **Free car** (`game/freecar.js`, `FREE_CAR` in config, styles in `windows.css` / `hud.css` `.free-btn`): the HUD's FREE! button counts down `FREE_CAR.minutes` of play on itself, lights up with a "!" when ready, opens a window (car card, progress bar, Claim) and hides once claimed. A guest's / offline play time is counted in the browser (visible tab only, `FREE_CAR.saveKey`); a signed-in player's by the server (backend `freeCar.ts`: `net.js` sends `freeCarSync` on join, `claimFreeCar()` asks before the car is given), one claim per account.
- **Tutorial** (`game/tutorial.js` + `tutorial.css`, `TUTORIAL` in config): new players get a banner under the To Shop / To Plot row (placed from the row's measured bottom) and instanced white ground arrows (ground height by `physics.groundBelow`) leading to the next thing: 0 buy a lucky block, 1 place it on a bay, 2 break it, 3 "Earn 400/1K Cash!" (goal = `TUTORIAL.pickaxe`'s price; arrows to the car's pad), then "You can now afford Iron Pickaxe!" flashes, 4 buy a pickaxe (arrows round the conveyor end, down the road to the Pickaxes Shop), 5 done. game.js `tutorialProgress` moves it on from what the player owns (works however they got it) and `tutorialRoute` builds the path. The step only rises; saved under `TUTORIAL.saveKey` and on the server (`net.js` `tutorialSync` on join / `sendTutorial`), the further one wins. A game save with no tutorial record counts as finished.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; used by nature.js).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
